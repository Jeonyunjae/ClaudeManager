# PRD (Product Requirements Document)
> 작성: planner | 상태: 수정 완료 (피드백 12건 반영)
> ClaudeManager v1.1 -- Skill-driven 멀티 AI 오케스트레이션 통합 관리 웹앱

---

## 1. 제품 비전

**"나(대표)를 위한, 나를 관리하는 AI 조직을 만든다."**

ClaudeManager는 1인 CEO를 위한 AI 기반 전용 조직 운영 시스템이다. Mac Mini에서 AI 오케스트레이터들이 하나의 조직처럼 동작하고, 대표는 웹 대시보드(대표실)에서 어디서든 이 조직을 감독, 지시, 승인한다.

핵심 전환점: Part를 하드코딩하지 않고, 대표가 **Part Skill(bash 스크립트)** 을 작성하여 **동적으로 Part를 생성**한다. MVP는 Skill 엔진 + 프로젝트 Part Skill 하나로 시작하며, 장기적으로 대표의 삶 전반을 관리하는 개인 AI 비서 시스템으로 확장한다.

### UI 방향성: 메타버스 스타일 가상 오피스
대시보드를 단순한 테이블/차트가 아닌 **메타 공간(가상 오피스)** 으로 구성한다.
- 각 에이전트(Main, Part, Sub, 인스턴스)를 **귀여운 캐릭터**로 시각화
- **Part = 부서 공간**, **Sub = 팀 공간**으로 메타 공간 내 구역을 나누어 표현
- 캐릭터들이 해당 공간에서 작업하는 모습으로 진행 상태를 직관적으로 전달
- 예: 프로젝트 Part 부서에 팀장 캐릭터(Sub)가 있고, 외주 인력 캐릭터(인스턴스)가 작업 중인 애니메이션
- 승인 대기 시 캐릭터가 대표실 앞에서 기다리는 등 상태를 시각적으로 표현
- 상세 컨셉(캐릭터 디자인, 공간 레이아웃, 애니메이션 등)은 **컨셉 결정 단계에서 구체화**

## 2. 목표

### 단기 목표 (MVP)
- Skill 엔진을 통한 동적 Part 생성 구조 구현
- 프로젝트 Part Skill 하나로 AI 개발 조직 운영
- 실시간 모니터링 대시보드를 통한 전체 에이전트 감독
- Human-in-the-Loop 의사결정 흐름 확립
- 서버 재시작 시 완전 자동 복구

### 장기 목표
- 다양한 Part Skill 추가로 삶 전반 관리 (재정, 일상, 투자 등)
- 로컬 LLM(Gemma 4) 전환을 통한 개인 데이터 완전 보호
- Agent SDK 전환을 통한 프로그래매틱 제어

### 성공 지표
| 지표 | 목표값 | 측정 방법 |
|---|---|---|
| 에이전트 가시성 | 모든 에이전트 상태를 1개 화면에서 확인 | 대시보드 커버리지 |
| 승인 응답 시간 | 승인 요청 발생 후 5분 이내 알림 수신 | 알림 지연 시간 측정 |
| 자동 복구 성공률 | 서버 재시작 후 95% 이상 자동 복구 | 복구 로그 분석 |
| Skill 확장성 | 새 Part 추가 시 코드 수정 없이 Skill만 작성 | Skill 기반 Part 생성 테스트 |
| 비용 추적 정확도 | 실제 API 비용 대비 95% 이상 일치 | 제공사 청구서 대조 |

## 3. 사용자 페르소나

### 대표 (Primary User)
- **프로필**: 1인 CEO, 기술 이해도 높음, 다수의 AI 프로젝트 동시 운영
- **주 사용 환경**: PC 데스크톱 브라우저 (주), 모바일 브라우저 (보조 -- 기본 모니터링 + 승인)
- **핵심 니즈**: 여러 AI 에이전트를 한 곳에서 감독, 중요 결정에 대한 즉시 알림, 서버 장애 시 자동 복구
- **불만**: 터미널 여러 개를 수동으로 관리하는 비효율, 에이전트 상태 파악 어려움, 승인 프로세스 부재

## 4. 기능 요구사항

### 4.1 Must Have (MVP 필수)

#### Skill 엔진
- Part Skill 실행 엔진 (schema / execute 모드)
- 기본 Skill 2개 제공: `base-part.sh`, `project-part.sh`
- 단일 상속 메커니즘 (`source` 기반)
- Skill 라이브러리 관리 (`~/.claudemanager/skills/`)
- 스키마 기반 입력 폼 UI 자동 생성
- Skill 버전 관리 (`skill-version.lock`, `input.json` 기록)

#### 4계층 오케스트레이션
- Main 오케스트레이터 (비서실장) 관리
- Part 오케스트레이터 (부서장) 동적 생성 및 관리
- Sub 오케스트레이터 (팀장) 관리
- 인스턴스 (외부 전문 인력) 관리
- Part 내 Sub 간 독립 운영 보장

#### 모니터링
- 전체 대시보드: Part/Sub/인스턴스 트리 구조, 실시간 상태
- 프로젝트 상세: Sub 오케스트레이터 + 인스턴스 트리, 승인 대기 강조
- 인스턴스 상세: 실시간 터미널 화면, 작업 로그
- 비용 대시보드: 모델별 토큰 사용량, API 비용 (일/주/월/프로젝트별), 임계값 알림
- Mac Mini 헬스: CPU/메모리/디스크/네트워크 모니터링, 임계값 알림

#### 제어
- 프로젝트 관리: 생성, 시작/일시정지/재시작/중단, 우선순위 변경
- 의사결정 승인 시스템: 승인/반려/수정 지시, 승인 이력 저장
- 인스턴스 모델 수동 선택: 모델 추천 카드(품질/속도/비용) 제공

#### Human-in-the-Loop
- Sub에서 Main으로 의사결정 전달
- Hook(HTTP POST)을 통한 웹앱 연동
- 대시보드에서 대표에게 알림
- 대표는 Main에게만 지시 (Sub 직접 지시 불가)
- 승인 없이 다음 단계 진행 불가

#### 알림
- 웹 대시보드: 승인 대기 배지, 실시간 알림
- 브라우저/모바일 푸시 알림
- 트리거: 승인 요청, 에이전트 오류+재시도 실패, 단계 완료, 비용 초과, 복구 완료

#### 오류 처리
- 에이전트 실패 시 자동 N회 재시도 (횟수/간격 설정 가능)
- 모든 재시도 실패 시 에이전트 정지 + 알림
- 오류 로그 전체 저장

#### API 키 관리 센터
- AI 제공사 API 키 웹 등록/갱신
- 키별 사용량 추적, 만료일 알림, 암호화 저장

#### 노트 기반 상태 관리 + 자동 복구
- `.orchestrator/` 폴더 기반 컨텍스트 관리
- Hooks 이벤트 시 노트 + DB 이중 기록
- 서버 재시작 시 자동 복구 흐름 (PM2 -> 백엔드 -> 스캔 -> tmux 재생성 -> 이어서 작업)

#### 이전 용이성
- 절대 경로 하드코딩 금지, 환경변수 기준
- 설정 외부화 (`.env` 또는 config 파일)
- 마이그레이션 스크립트 (`migrate-to-new-machine.sh`) 포함

#### AI Gateway
- 모든 모델 호출 LiteLLM 경유 (직접 API 호출 금지)
- Part Skill에 `MODEL_ROUTING` 필드
- DB에 `model_provider` 컬럼

#### 양방향 터미널 제어
- 웹앱에서 Claude CLI로 명령을 보내는 양방향 터미널 제어
- tmux + node-pty + Hooks를 통한 stdin/stdout 완전 제어
- 인스턴스 상세 뷰에서 터미널 표시 + 입력(stdin) 전송 기능

#### 대표 지시 인터페이스
- 대표가 능동적으로 Main에게 새로운 지시를 내리는 채팅/명령 UI
- 승인 처리 외에도 "이 프로젝트 우선순위 올려" 같은 능동적 지시 가능
- 대표의 지시 이력 저장

#### 감사 로그 (Audit Trail)
- 시스템 전체 행동 감사 로그
- 대표의 지시/승인/반려 이력 전체 기록 (누가, 언제, 무엇을)
- 에이전트 행동 로그 (디버깅 + 사후 분석용)

#### 설정/환경설정 UI
- 재시도 횟수/간격, 알림 임계값, 비용 한도 등을 웹에서 설정
- Part별 정책(승인, 재시도, 민감도)을 UI에서 관리
- 대표가 코드 수정 없이 직접 조정 가능

#### 검색/필터링
- 승인 이력, 오류 로그, 비용 내역 등의 검색/필터링
- 기간별, Part별, 상태별 필터링
- 로그 검색

#### 데이터 백업/복원
- SQLite DB + `.orchestrator/` 파일의 자동 백업
- 자동 백업 주기 설정, 복원 절차 제공
- Mac Mini 이전 시 데이터 보전 보장

#### 동시 에이전트 리소스 관리
- 동시 실행 에이전트 수 상한 설정
- 상한 초과 시 큐잉 또는 대표에게 확인 요청
- CPU/메모리 기반 자동 제한

#### 인프라/배포
- Vercel 배포 설정
- PM2 + macOS launchd 프로세스 관리 설정
- 개발 환경 구성 (환경변수, 의존성 설치 등)

### 4.2 Nice to Have (Phase 2)
- 인스턴스 모델 자동 선택 (축적 데이터 기반)
- AI 모델 성능 비교 대시보드
- 스케줄링/자동 실행 (Cron 스타일)
- 상세 분석 리포트 (비용, 생산성, 오류율)
- 알림 채널 확장 (Slack/Discord)
- 프로젝트 템플릿
- Agent SDK 전환
- 온보딩/초기 설정 마법사 (최초 실행 시 환경변수, API 키, Skill 경로 등 가이드 위자드)

### 4.3 Out of Scope
- 네이티브 모바일 앱 (Phase 3)
- 다중 사용자/팀 기능
- 자체 AI 모델 학습/파인튜닝
- 금융 쓰기 API (구조적으로 영구 차단)

## 6. DB 저장 데이터 명세

### 노트(파일) vs DB 역할 분담

| 저장소 | 역할 | 예시 |
|---|---|---|
| `.orchestrator/*.md` | 오케스트레이터가 읽고 이어서 작업하는 **컨텍스트** | context.md, decisions/, progress/ |
| **SQLite DB** | 대시보드가 빠르게 조회하는 **구조화된 상태** | 에이전트 트리, 승인 큐, 비용 집계, 알림 |

- 노트 = 에이전트의 "인수인계 문서", DB = 대시보드의 "조회용 데이터 소스"
- Hooks가 이벤트 발생 시 양쪽에 동시 기록

### DB 저장 데이터 카테고리

1. **에이전트/세션 관리**: Part 정보(part_id, skill_name, skill_version, sensitivity_level, model_provider, 상태), Sub 오케스트레이터(sub_id, part_id, 프로젝트명, 진행 단계, 상태), 인스턴스(instance_id, sub_id, 모델명, 태스크 유형, 상태, tmux 세션 ID)
2. **의사결정/승인 (Human-in-the-Loop)**: 승인 요청(출처, 내용, 긴급도), 승인 이력(승인/반려/수정지시, 코멘트, 처리 시각)
3. **비용/토큰 추적**: API 호출 로그(instance_id, 모델명, 입력/출력 토큰, 비용, 타임스탬프), 일/주/월/프로젝트별 비용 집계
4. **알림**: 트리거 유형(승인요청/오류/완료/비용초과/복구), 대상, 읽음 여부, 발생 시각
5. **오류/재시도**: 오류 로그(에러 메시지, 스택 트레이스, 재시도 횟수, 최종 상태), Part별 재시도 정책(횟수/간격)
6. **API 키 관리**: 제공사, 키(암호화), 만료일, 사용량, 상태
7. **프로젝트 진행 상태**: 단계별 진행률, 시작/완료 시각
8. **Skill 메타데이터**: skill_name, 버전, 상속 관계, 스키마 정의, 등록일
9. **시스템 헬스 (시계열)**: CPU/메모리/디스크/네트워크, 타임스탬프

## 7. 비기능 요구사항

### 성능
- 대시보드 실시간 업데이트 지연: 2초 이내 (WebSocket)
- 승인 요청 알림 전달: 5초 이내
- DB 조회 응답: 200ms 이내
- 동시 에이전트 세션: 최소 10개

### 보안
- 데이터 민감도 3단계: 극민감(암호화 필수) / 민감(로컬 전용) / 일반(기본 저장)
- API 키 암호화 저장
- 금융 쓰기 API 구조적 차단
- 승인 정책 Part별 분리 (전역 하드코딩 금지)
- 인증 방식: 1인 사용자에 적합한 간단한 인증 (설계 단계에서 결정)

### 확장성
- Skill 기반 Part 동적 추가 (코드 수정 불필요)
- 외부 연동은 MCP 커넥터 레이어 경유
- 모델 호출 LiteLLM 경유 (로컬 LLM 전환 대비)
- Part Skill에 `MODEL_ROUTING` 필드 (모델 라우팅 유연성)

### 안정성
- 노트 + DB 이중 저장으로 데이터 유실 방지
- PM2 + macOS launchd 기반 프로세스 자동 복구
- 서버 재시작 시 완전 자동 복구 (95% 이상)

### 이식성
- MacBook(개발) -> Mac Mini(운영) 원활한 이전
- 환경변수 기반 경로 관리
- 마이그레이션 스크립트 제공

## 8. 제약 조건

- **하드웨어**: MacBook(Phase A 개발), Mac Mini Pro(Phase B 운영)
- **네트워크**: Phase A는 로컬 전용, Phase B에서 외부 접근 방식 결정
- **1인 사용자**: MVP에서는 단일 사용자만 지원
- **Claude Code 의존성**: 오케스트레이터는 반드시 Claude Code 사용 (파일 시스템 접근, 도구 실행, Hooks 필수)
- **하드코딩 Part 금지**: 모든 Part는 Skill을 통해서만 생성

---

## 9. 가정

- 대표는 bash 스크립트 작성이 가능하다
- Claude Code의 Hooks API가 안정적으로 동작한다
- LiteLLM이 필요한 모든 AI 모델을 지원한다
- Mac Mini Pro가 Phase B 시점에 확보된다
- tmux 세션이 안정적으로 유지된다

---

## 10. 의존성

- **Claude Code**: 오케스트레이터 실행 런타임
- **Claude Code Hooks**: 이벤트 수집 및 양방향 제어
- **LiteLLM**: AI 모델 통합 게이트웨이
- **tmux**: 세션 관리 및 터미널 릴레이
- **PM2 + macOS launchd**: 프로세스 관리 및 자동 복구

## 11. MVP 범위 정의

### MVP에 포함
1. Skill 엔진 (base-part.sh, project-part.sh, 단일 상속, 스키마 기반 폼)
2. 4계층 오케스트레이션 구조 (Main -> Part -> Sub -> 인스턴스)
3. 실시간 모니터링 대시보드 (에이전트 트리, 터미널, 비용, 헬스, 메타버스 UI)
4. Human-in-the-Loop 의사결정 흐름
5. 알림 시스템 (웹 대시보드 + 브라우저 푸시)
6. 오류 처리 및 자동 재시도
7. API 키 관리 센터
8. 노트 기반 상태 관리 + 자동 복구
9. 인스턴스 모델 수동 선택 (추천 카드 포함)
10. 이전 용이성 설계 (환경변수, 마이그레이션 스크립트)
11. 양방향 터미널 제어 (웹앱에서 CLI로 stdin 전송)
12. 대표 지시 인터페이스 (Main에게 능동적 지시)
13. 감사 로그 (시스템 전체 행동 이력)
14. 설정/환경설정 UI (Part별 정책, 임계값 웹 관리)
15. 검색/필터링 (이력, 로그, 비용 내역)
16. 데이터 백업/복원 (자동 백업, 복원 절차)
17. 동시 에이전트 리소스 관리 (상한, 큐잉, 자동 제한)
18. 인프라/배포 설정 (Vercel, PM2+launchd, 개발 환경 구성)

### MVP에서 제외 (Phase 2 이후)
- 모델 자동 선택
- 스케줄링/자동 실행
- 분석 리포트
- 알림 채널 확장
- Agent SDK 전환
- 로컬 LLM 전환 (Phase B/C)
- 온보딩/초기 설정 마법사
