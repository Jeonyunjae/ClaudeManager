# 컨셉 결정
> ✏️ 작성 완료 후 CLI에서 **"컨셉 결정 완료"** 입력

---

## 1. 제품 한 줄 정의

**"나와 AI 동료들이 함께 일하는 메타버스 워크스페이스"**

웹 브라우저를 열면 내가 속한 가상 공간이 펼쳐진다. 귀여운 AI 캐릭터들이 내 주변에서 각자의 자리에서 일하고, 나에게 다가와 보고하고, 함께 대화한다. 나는 이 공간 안에 존재하며, AI 동료들과 같은 공간에서 프로젝트를 함께 수행한다.

## 2. 핵심 가치 (이 제품이 주는 경험)

### 함께 있다는 느낌
- 나의 아바타가 공간 안에 존재하고, AI 동료들이 주변에서 일하는 모습을 볼 수 있다
- 위에서 내려다보는 것이 아니라, **같은 레벨에서 옆을 바라보는** 공존의 시점
- 캐릭터들이 실제로 움직이며 일하는 모습 — "혼자가 아니구나"를 직관적으로 느낌
- 메타버스처럼 내가 이 세계의 일부라는 몰입감

### 대화형 프로젝트 수행
- 프로젝트의 모든 진행은 **나 ↔ Main 간 채팅 대화**로 이루어짐
- 내가 채팅으로 지시 → Main이 대화로 보고/질문/승인 요청
- 대화 흐름 속에서 자연스럽게 의사결정이 진행됨
- 채팅 UI가 프로젝트 수행의 **주 인터페이스**

### 결정사항의 자동 정리 + 리포트 열람
- 대화 중 결정된 사항은 `.orchestrator/` **Obsidian 노트에 자동 정리**
- 노트를 파싱하여 웹앱 대시보드에서 **리포트 형식으로 열람** 가능
- 대화는 휘발되지만, 결정사항/진행 상황은 구조화된 문서로 남음
- 리포트 예시: 프로젝트 진행 보고서, 의사결정 이력, 비용 리포트, 에이전트 활동 요약

### 직관적 상태 파악
- 캐릭터의 행동/표정/위치만으로 에이전트 상태를 즉시 인지
- 숫자와 텍스트가 아닌 **공간과 움직임**으로 정보 전달
- 문제가 생기면 캐릭터가 당황하거나 빨간 표시 → 내 근처에서 즉시 인지

### 접촉 기반 상호작용
두 가지 방향의 상호작용이 존재한다:

**내가 다가감 (사용자 주도)**
- 내 캐릭터를 움직여 에이전트(Main, Sub, 인스턴스) 위치로 이동
- 에이전트에 접촉하면 해당 에이전트의 상세 팝업이 열림
- 상태 확인, 대화 내역 열람, 노트/로그 조회 등 탐색 목적

**오브젝트가 다가옴 (에이전트 주도)**
- 승인 요청: 에이전트가 내 캐릭터 위치로 이동 → 접촉 → 승인 팝업 표시
- 리포트 전달: 에이전트가 다가와 접촉 → 리포트 팝업 표시
- 오류 알림: 에이전트가 당황 모션으로 달려와 접촉 → 오류 상세 팝업
- 마치 같은 공간에서 동료가 직접 찾아오는 자연스러운 흐름

## 3. 채팅 톤앤매너

### Main(비서실장)의 말투
- **기본 어투**: 존댓말 비서체 — 친근하지만 격식 있는 보고 톤
- 보고: "프로젝트부에서 개발 1단계가 완료되었습니다. 다음 단계 진행할까요?"
- 승인 요청: "프로젝트부 김팀장이 결재를 올렸습니다. 확인 부탁드립니다."
- 오류 보고: "프로젝트부 Sub-A에서 오류가 발생했습니다. 3회 재시도 모두 실패했습니다."
- 완료 보고: "프로젝트부 전체 작업이 완료되었습니다. 리포트를 정리해두었습니다."
- 질문: "기술 스택 관련 결정이 필요합니다. A안과 B안 중 어느 쪽으로 진행할까요?"

### 알림 메시지 톤
- 푸시 알림도 캐릭터가 말하는 형식으로 통일
- 승인 요청: "비서실장: 프로젝트부에서 결재가 올라왔습니다"
- 오류: "비서실장: 프로젝트부에서 문제가 발생했습니다. 확인 부탁드립니다"
- 완료: "비서실장: 개발 1단계가 완료되었습니다"
- 비용 초과: "비서실장: 이번 달 API 비용이 설정 한도에 도달했습니다"

## 4. 비주얼 톤앤매너

### 분위기
- **3D 카툰 렌더링 메타버스 워크스페이스 (데스크톱)** — 로우폴리 카툰 스타일의 따뜻하고 몽환적인 공유 공간
- 부드러운 파스텔 톤 + 비비드 포인트 색상 (핑크, 민트, 라벤더, 연두)
- 소프트 라이팅 + 보케 효과 + 깊이감(DOF)으로 드리미한 분위기
- 정보 밀도가 높되 복잡하지 않은 — 3D 공간과 데이터 UI를 레이어드
- 레퍼런스: **Versa Metaverse Landing Page** (Dribbble) 스타일

### 키워드
- 공존, 생동감, 몽환적, 따뜻함, 직관적, 메타버스, 함께하는 공간

### 캐릭터 스타일
- **2~3등신 로우폴리 3D 카툰 캐릭터** (슬라임/로봇/동물이 아닌 작은 사람형)
- 부드러운 라운드 형태, 큰 머리 비율, 따뜻한 질감
- **나(대표) 아바타**: 공간 안에 존재하는 나의 분신. 내 데스크에 앉아있거나 공간을 돌아봄
- 역할별 복장으로 구분:
  - Main(비서실장): 정장 + 안경
  - Part(부서장): 부서별 색상 유니폼
  - Sub(팀장): 해당 부서 색상 + 팀 배지
  - 인스턴스(외주): 프리랜서풍 캐주얼 + 노트북
- 상태별 3D 애니메이션:
  - 작업 중: 키보드 타이핑 모션
  - 대기 중: 커피 마시기, 기지개
  - 승인 대기: 내 캐릭터에게 걸어와 접촉 → 승인 팝업 트리거
  - 오류: 머리 위 이펙트 + 당황 모션
  - 완료: 기쁨 점프 모션 + 파티클 이펙트

### 공간 구성 (공유 워크스페이스)
```
┌─────────────────────────────────────────┐
│          🏢 공유 워크스페이스              │
│                                         │
│  ┌──────┐  ┌──────┐                     │
│  │ 🧑 내 │  │ Main │  (나와 Main이       │
│  │ 데스크 │  │ 데스크 │   나란히 위치)      │
│  └──────┘  └──────┘                     │
│                                         │
│  ┌─────────────┐  ┌─────────────┐       │
│  │ 🏭 프로젝트  │  │ 🏭 (미래 확장) │      │
│  │  부서 구역    │  │  Skill로 추가 │      │
│  │ ┌────┐┌────┐│  │  시 새 구역   │      │
│  │ │SubA││SubB││  │  생성        │      │
│  │ └────┘└────┘│  │             │      │
│  └─────────────┘  └─────────────┘       │
│                                         │
├─────────────────────────────────────────┤
│ 📊 상단 메뉴: 워크스페이스 | 대시보드 | 설정 | 리소스 관리 │
│ 📊 하단 바: 에이전트 수 | 비용 | 헬스          │
└─────────────────────────────────────────┘
```
- **시점**: 아이소메트릭이되, 나(대표) 아바타 중심의 **근접 시점**. 내 데스크 주변이 크게 보이고, 부서들은 자연스럽게 주변으로 펼쳐짐
- **나의 위치**: 공간의 중심이 아닌, 공간의 일부. Main 옆자리에 나란히 앉아있는 구조
- **캐릭터 이동**: 내 아바타를 움직여 에이전트에게 다가가면 접촉 → 팝업
- **에이전트 접근**: 승인/리포트/오류 시 에이전트가 내 위치로 걸어와 접촉 → 팝업

### 색상 팔레트
| 용도 | 색상 | 의미 |
|---|---|---|
| 기본 배경 | 연한 크림/베이지 | 따뜻한 공유 공간 바닥 |
| 작업 중 | 파란 계열 | 정상 진행 |
| 승인 대기 | 노란/주황 | 주의 필요 |
| 오류 | 빨간 계열 | 즉시 확인 |
| 완료 | 초록 계열 | 성공 |
| Part별 구분 | 부서별 고유 색상 | 공간 구분 |

### 상단 메뉴 구성 (데스크톱)
- **워크스페이스**: 3D 메타버스 공간. 내 캐릭터를 움직여 에이전트와 접촉하여 상호작용. 채팅도 Main에게 다가가면 팝업으로 열림
- **대시보드**: 리포트(진행 보고, 활동 요약, 의사결정 이력) + 비용 차트 + 승인 이력 등 데이터 통합 뷰
- **설정**: 전역 설정, Part별 정책, 백업/복원
- **리소스 관리**: API 키 관리, 에이전트 상한, 비용 한도, 에이전트 생성/삭제/설정

### 상세 팝업 모달 (접촉 시)
- 워크스페이스에서 에이전트에 접촉하면 넓은 팝업 모달이 열림 (화면 80%)
- 탭: 대화 / 노트 / 로그 / 터미널
- 에이전트가 다가왔을 때도 동일한 팝업이 열리되, 승인/리포트 등 해당 컨텍스트가 먼저 표시됨

## 5. 모바일 경험

### 기본 방침
- 모바일은 **진행상황 + 잔여업무 + 의사결정** 중심의 실용 뷰
- 3D 워크스페이스는 모바일에서 로딩하지 않음 (번들 자체를 분리하여 성능 영향 zero)

### 모바일 UI 구성
- **채팅 뷰 (기본)**: Main과의 대화 — 지시/보고/승인 처리
- **진행상황**: 프로젝트별 진행률, 단계별 상태 요약
- **잔여업무**: 대기 중인 작업, 승인 대기 항목 목록
- **의사결정**: 결정 필요 항목 하이라이트, 빠른 승인/반려
- **알림 목록**: 승인 대기, 오류, 완료 알림을 목록으로 표시
- 상세 터미널, 데이터 뷰, 3D 워크스페이스 뷰는 데스크톱 전용

## 6. 첫 경험 (온보딩)

### 최초 접속
- 공유 공간에 **내 데스크와 Main(비서실장) 캐릭터**가 있음
- 나의 아바타가 공간에 등장하면, Main이 다가와 접촉 → 인사 팝업: "안녕하세요, 함께 일하게 된 비서실장입니다. 첫 부서를 만들어볼까요?"
- 자연스럽게 첫 Skill 실행으로 유도
- 이후 Main에게 다가가면 채팅 팝업이 열리는 것을 자연스럽게 학습

### 첫 Part 생성 시
- Skill 실행 → 워크스페이스에 **새 부서 구역이 건축되는 애니메이션**
- 공사 이펙트(망치질하는 캐릭터) → 완성 → Part(부서장) 캐릭터 배치
- Main이 채팅으로 보고: "프로젝트부가 설립되었습니다. 첫 프로젝트를 시작할까요?"

### 이후 Part 추가 시
- 동일한 건축 애니메이션으로 워크스페이스 확장
- 기존 구역 옆에 새 부서 구역이 추가됨

## 7. 리포트 뷰 형식

### 표시 방식
- `.orchestrator/` 노트의 마크다운을 **파싱하여 카드형 리포트로 렌더링**
- 단순 마크다운 뷰어가 아닌, 구조화된 UI로 표시

### 리포트 유형
| 리포트 | 소스 노트 | 표시 형식 |
|---|---|---|
| 프로젝트 진행 보고서 | progress/*.md | 단계별 타임라인 + 완료율 바 |
| 의사결정 이력 | decisions/*.md | 시간순 카드 목록 (질문 → 결정 → 근거) |
| 비용 리포트 | (DB 집계) | 차트 + 모델별 비용 테이블 |
| 에이전트 활동 요약 | (DB 집계) | 에이전트별 작업 시간/완료 건수 |
| 오류 리포트 | (DB 집계) | 오류 유형별 분류 + 해결 상태 |

### 리포트 내비게이션
- Part 탭 → 해당 부서의 리포트 목록
- 날짜 필터, 리포트 유형 필터 제공

## 8. 에이전트 활동 열람

### 기본 방침
- 모든 계층(Main, Part, Sub, 인스턴스)의 활동을 웹앱에서 열람 가능
- 캐릭터 클릭 → 상세 패널에서 해당 에이전트의 모든 활동 확인

### 계층별 열람 내용

| 계층 | 대화 내용 | 정리 내용 | 로그 |
|---|---|---|---|
| **Main** | 나와의 채팅 이력, Part들에게 내린 지시 | main-context.md | 시스템 전체 이벤트 로그 |
| **Part** | Sub들에게 내린 지시, Sub로부터 받은 보고 | part-context.md, decisions/ | Part 단위 이벤트 로그 |
| **Sub** | 인스턴스들에게 분배한 태스크, 진행 보고 | sub-context.md, progress/ | Sub 단위 작업 로그 |
| **인스턴스** | (대화 없음, 태스크 수행만) | 작업 결과 출력 | 실시간 터미널(xterm.js), 상세 작업 로그 |

### 팝업 모달 구성 (캐릭터 접촉 시)
- 내가 에이전트에게 다가가 접촉하거나, 에이전트가 나에게 다가와 접촉하면 **넓은 팝업 모달**이 열림 (화면 80% 크기)
- 상단: 캐릭터 아이콘 + 이름 + 역할 + 현재 상태
- **탭 1. 대화**: 해당 에이전트의 대화 내용 (지시/보고/질문 시간순)
- **탭 2. 노트**: `.orchestrator/` 정리 내용 (context.md, decisions/, progress/) 마크다운 렌더링
- **탭 3. 로그**: 이벤트 로그 타임라인 (Hooks 수집 데이터)
- **탭 4. 터미널**: 실시간 터미널 화면 (xterm.js, 양방향 제어)
- ESC 또는 바깥 클릭으로 닫기

### 대화 흐름 시각화
- Main → Part → Sub → 인스턴스 간 **지시/보고 흐름을 트리형 타임라인**으로 표시
- 어떤 지시가 어떤 하위 작업으로 분배되었는지 추적 가능
- 예: "나의 지시 → Main이 Part에 전달 → Part가 Sub-A, Sub-B에 분배 → 각 인스턴스 작업"

### 데이터 소스
- **대화 내용**: Hooks가 에이전트 간 통신 이벤트를 DB에 기록
- **정리 내용**: `.orchestrator/` 노트 파일을 chokidar로 감시, 변경 시 웹앱에 실시간 반영
- **로그**: Hooks 이벤트 + 에이전트 stdout/stderr 수집

## 12. 절대 하지 않을 것 (Anti-pattern)

- **위에서 내려다보는 관찰자 시점**: 대표실에서 조직을 감시하는 느낌. 함께 있는 것이지, 위에서 보는 것이 아니다
- **숫자/텍스트 나열형 대시보드**: 생명력 없는 테이블만 나열하지 않는다
- **과도한 하이폴리 3D**: 모니터링 도구가 게임보다 무거워지면 안 된다. 로우폴리 + 최적화로 가볍게
- **캐릭터가 정보를 가리는 UI**: 귀여움이 기능을 방해하면 안 된다. 워크스페이스 뷰와 데이터 뷰를 분리
- **너무 유치한 톤**: 귀엽되 전문적인 느낌 유지. 장난감이 아니라 함께 일하는 공간
- **캐릭터 커스터마이징 기능**: MVP에서 캐릭터 꾸미기는 하지 않는다
- **Gather Town식 멀티플레이어**: 다른 사용자와의 실시간 동시 접속은 불필요. 1인 사용자 + AI 에이전트 간의 접촉 상호작용에 집중
