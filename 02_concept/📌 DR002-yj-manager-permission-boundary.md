## 0. 용어 정의 (이 문서 읽기 전에)

| 용어 | 정의 |
|---|---|
| **YJ Manager** | 대표의 여러 프로그램(ClaudeManager, MyLife Friend, Location, Finance Bot 등)에 대한 **외부 접근 권한 원천**. 각 자매 프로그램이 어느 폴더/자원을 건드릴 수 있는지를 결정한다. |
| **자매 프로그램** | YJ Manager가 관리하는 대표 소유 프로그램들. **서로 동등한 레벨**이며 총괄 관계가 아니다. 현재: ClaudeManager, MyLife Friend, Location, Finance Bot (+ 05.Finance 워크스페이스). |
| **ClaudeManager** | 본 DR의 주체. 1인 CEO를 위한 AI 조직 운영 플랫폼. |
| **권한 경계** | 한 자매 프로그램이 **건드릴 수 있는 파일/폴더/자원의 범위**. |
| **교차 접근** | 자매 프로그램 A가 자매 프로그램 B의 자원을 읽거나 쓰는 것. |

## 1. 결정 배경 (Context)

DR001에서 확정된 것:
- ClaudeManager는 YJ Manager의 자매 프로그램 중 **하나**이며, 다른 자매 프로그램(MyLife Friend, Location, Finance Bot)을 총괄하지 않음.
- YJ Manager는 ClaudeManager의 **외부 접근 권한 원천**.

DR001에서 **결정 유보**된 것 (→ 본 DR002에서 다룸):
- YJ Manager가 자매 프로그램들 간에 **어떤 권한 경계**를 그을 것인지.
- 자매 프로그램끼리 **서로의 자원을 읽거나 쓸 수 있는지**.
- **허용 vs 차단**의 기본값은 무엇인지.

이 결정이 필요한 이유: ClaudeManager Sub가 프로젝트 폴더 밖(예: Finance Bot 폴더)을 실수로 건드리는 사고를 막으려면 권한 경계가 선행 정의되어 있어야 함.

## 3. 옵션 비교

| 기준 | A. 완전 격리 (기본 차단) | B. 읽기만 공유 | C. YJ Manager가 매번 명시 허용 |
|---|---|---|---|
| **기본 동작** | 자매 프로그램끼리 서로의 폴더 접근 ✗ | 읽기는 자유, 쓰기는 ✗ | 접근 시마다 YJ Manager 레지스트리에 등록 필요 |
| **예시 · ClaudeManager Sub → Finance Bot 폴더** | ✗ 불가 | ✅ 읽기 가능 (예: 리포트 참조), ✗ 쓰기 불가 | 등록된 경우만 가능 |
| **실수 방지** | ✅ 강함 — 기본이 차단 | △ 읽기는 무제한이라 스캔/집계 유출 가능 | ✅ 강함 |
| **공유 편의성** | ✗ 공유 시 매번 경로 복사 등 수작업 | ✅ 편리 (읽기 중심) | △ 등록 절차 번거로움 |
| **Finance Bot이 05.Finance 워크스페이스 노트 읽기** | ✗ 별도 심볼릭 링크 필요 | ✅ 자연스러움 | 등록 필요 |
| **금융 실행 차단 (메모리 원칙)** | ✅ 근본 차단 | △ 읽기만 허용이라 "실행"은 원천 불가 | ✅ 등록 안 된 쓰기는 차단 |
| **설정 복잡도** | 중 | 낮음 | 높음 (레지스트리 운영) |
| **권한 시각화 (대시보드)** | ✅ 단순 | △ 읽기/쓰기 구분 필요 | ✅ 레지스트리 뷰 필요 |

## 4. 판단 기준

- **안전 기본값 원칙**: 실수·사고는 "기본이 허용"일 때 잘 생김. 자매 프로그램 간 교차 접근은 기본적으로 **차단**이 안전.
- **유용성**: 그렇다고 완전 격리(A)만 고수하면 Finance Bot이 05.Finance 워크스페이스를 참조할 때처럼 자연스러운 공유가 불편해짐.
- **실행(쓰기)은 더 엄격해야 함**: 메모리에 "금융 실행 절대 금지" 원칙이 있듯, 쓰기는 읽기보다 높은 허들이 필요.
- **YJ Manager 운영 부담**: 매번 레지스트리에 등록하는 C안은 자매 프로그램 수가 늘수록 피곤함.

---

## 5. Sub 권장안

→ **옵션 B (읽기만 공유) + 예외 화이트리스트**.

구성:
1. **기본값**: 자매 프로그램은 다른 자매의 폴더를 **읽기만** 가능. 쓰기는 **기본 차단**.
2. **쓰기 예외**: YJ Manager 화이트리스트에 등록된 (출발지 → 목적지) 쌍만 쓰기 허용.
3. **금융 실행 등 특수 범주**: 아예 허용 화이트리스트에도 못 올라옴 (물리 차단).
4. **감사 로그**: 모든 교차 접근(읽기 포함)은 YJ Manager 로그에 기록.

사유: A의 안전성과 B의 편의성을 절충하되, 쓰기만 C처럼 엄격하게 운영.

단, 대표가 "읽기조차도 자동 허용은 싫다" 면 옵션 A (완전 격리 + 필요 시 개별 허용).
