# 설계 피드백 — UI 철학
> 검토 후 작성하고 CLI에서 **"피드백 완료"** 입력

## 상태
✅ 승인 — UI 철학 문서(ui-concept.md) 승인 완료

## 피드백

### 1. 채팅 대화 예시 대폭 보강
- 현재 Main의 대화가 1~2줄로 너무 짧음
- 각 시나리오에서 **대표 ↔ Main 간 실제 대화를 최소 5~8턴** 예시로 작성
- Main의 비서체 말투 일관성 유지 (컨셉 결정 섹션 3 참조)
- 보고, 질문, 옵션 제시, 승인 요청 등 대화 유형별로 다양하게

### 2. 오피스 뷰 시각 연출 구체화
- "캐릭터가 나타난다" 수준이 아니라, **구체적 시각 연출** 묘사 필요
- 예: "Sub 캐릭터가 부서 공간 왼쪽 책상에 앉아 타이핑 모션 시작. 머리 위에 '기획 중' 말풍선 표시. 30초 후 인스턴스 캐릭터 2명이 오른쪽 책상에 나란히 앉으며 노트북 펼침"
- 캐릭터의 위치, 모션, 말풍선, 이펙트를 단계별로 묘사

### 3. 예외흐름 상세화
- 현재 예외흐름이 한 줄짜리로 너무 간략함
- 오류 시 **캐릭터 반응 + Main의 보고 대화 + 대표의 선택지**까지 상세 흐름으로 작성
- 예: 인스턴스 오류 시 → 캐릭터 머리 위 ❗ + 당황 모션 → Main이 채팅으로 "프로젝트부에서 오류가 발생했습니다. 재시도 중입니다 (1/3)" → 3회 실패 → 캐릭터 정지 모션 → Main "모든 재시도 실패. 수동 확인이 필요합니다. 터미널을 열어볼까요?" → 대표 "열어줘" → 팝업 모달 터미널 탭 자동 오픈

### 4. 시나리오 간 연결 흐름 강화
- SC-001 → SC-002 → SC-003이 자연스럽게 이어지는 **연속 스토리라인** 구성
- 각 시나리오 끝에 "다음 시나리오 연결" 섹션 추가
- 핵심 시나리오(SC-001~SC-010)는 하나의 연속된 이야기로 읽을 수 있도록

### 5. 대표의 경험/감정 묘사 추가
- 각 시나리오에 **"대표 경험"** 섹션 추가
- 대표가 이 흐름에서 어떤 느낌을 받는지, 어떤 가치를 체감하는지
- 예: "대표는 빈 오피스에 비서실장만 서있는 모습을 보며, 이제부터 이 공간이 채워질 것이라는 기대감을 느낀다"

### 6. UI 전환 묘사 추가
- 뷰 전환(오피스 뷰 → 채팅 뷰 → 리포트 뷰) 시 **화면이 어떻게 바뀌는지** 묘사
- 팝업 모달 열림/닫힘의 애니메이션 묘사
- 모바일과 데스크톱의 차이점도 해당 시나리오에서 명시

### 7. SC-002, SC-011, SC-016은 이미 직접 수정 완료 (참고용 품질 기준)
- SC-002: 방법론 탐색 대화, 팀 구성, 스키마 설명, 오피스 연출, 대표 경험 포함
- SC-011: Main과 대화 기반 API 키 관리, 사용량 보고
- SC-016: 기본값 10개 + 설정 조절 + 리소스 안전장치 + Main 보고
- SC-029: 노트 구조 및 작성 흐름 신규 추가
- **나머지 시나리오도 이 수준으로 품질 개선 필요**
