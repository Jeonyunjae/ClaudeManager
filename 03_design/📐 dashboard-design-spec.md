## 1. 비즈니스 흐름도

### 1-1. 전체 작업 시나리오

```
대표 (웹 대시보드 / CLI)
  |
  |  1. 프로젝트 지시 (채팅 또는 CLI)
  v
Main (비서실장)
  |
  |  2. Part 선택/생성 판단
  |     - 기존 Part 있으면 선택
  |     - 없으면 대표와 대화로 Skill 작성 -> Part 생성
  v
Part (부서장)
  |
  |  3. Sub 생성 (프로젝트 단위)
  |     - 해당 Part의 Skill로 구성
  |     - 대표가 Main과 대화하여 배치 정의
  v
Sub (팀장)
  |
  |  4. Instance 배치 및 작업 지시
  |     - 태스크 분배
  |     - 모델 선택 (수동/추천)
  v
Instance (에이전트)
  |
  |  5. 작업 수행
  |     - CLI에서 실제 작업 실행
  |     - 결과/진행 상황 기록
  v
보고 흐름 (역순)
  Instance -> Sub -> Part -> Main -> 대표
  |
  |  6. 보고 수신
  |     - Main이 대표에게 채팅으로 보고
  |     - 승인 필요 시 승인 요청 팝업
  v
대표 의사결정
  |
  |  7. 승인/반려/수정 지시
  |     - 승인: 다음 단계 진행
  |     - 반려: 사유와 함께 재작업 지시
  |     - 수정 지시: 방향 변경 후 재작업
  v
작업 계속 또는 완료
```

### 1-2. 사용자 개입 시나리오

| 상황 | 트리거 | 대표 행동 | 경로 |
|------|--------|----------|------|
| 작업 우선순위 변경 | 대표 판단 | Main에게 채팅으로 지시 | 채팅 패널 -> Main |
| 비용 한도 초과 | 알림 (자동) | 확인 후 계속/중단 결정 | 알림 -> 승인 팝업 |
| 에러 발생 | 알림 (자동) | 에러 로그 확인 -> 수동 복구 | 카드 클릭 -> 로그 탭 |
| 에이전트 정지/재시작 | 대표 판단 | Main에게 채팅으로 요청 | 채팅 패널 또는 카드 팝업 |
| 새 프로젝트 시작 | 대표 판단 | Main에게 채팅으로 지시 | 채팅 패널 -> Main |

### 1-3. 데이터 흐름

```
[Claude Code Hooks]
    |
    | HTTP POST (이벤트 발생 시)
    v
[백엔드 API (Next.js)]
    |
    +---> [SQLite DB] (구조화된 상태 저장)
    |
    +---> [.orchestrator/*.md] (에이전트 컨텍스트 저장)
    |
    +---> [WebSocket] (실시간 푸시)
              |
              v
       [대시보드 UI] (실시간 반영)
```

## 2. 화면 체계

### 2-1. 전체 화면 목록

| 화면 | URL | 역할 | 비고 |
|------|-----|------|------|
| 로그인 | `/login` | 비밀번호 인증, JWT 발급 | 1인 사용자 간단 인증 |
| 대시보드 | `/dashboard` | 메인 화면. 4컬럼 카드 플로우 + 활동 로그 + 상태 차트 | **이 문서의 주 대상** |
| 설정 | `/settings` | 전역 설정, Part별 정책, 백업/복원, 알림 임계값 | 풀스크린 모달 |
| 리소스 관리 | `/resources` | API 키 관리, 에이전트 상한, 비용 한도, 감사 로그 | 테이블 기반 |
| 워크스페이스 | `/workspace` | 3D 메타버스 가상 오피스 (추후) | Phase 2 |

### 2-2. 네비게이션 구조

```
TopNav (상단 고정)
+----------------------------------------------------------------------+
|  [로고]  대시보드* | 워크스페이스(추후) | 설정 | 리소스 관리   (벨)(프로필) |
+----------------------------------------------------------------------+
```

- 활성 탭: 하단 2px 보더 (`--primary-500`)
- 알림 벨: 미확인 알림 수 뱃지 (빨간 원형)
- 프로필: 클릭 시 로그아웃 드롭다운

### 2-3. 화면 간 관계

```
로그인 --> 대시보드 (메인)
              |
              +---> 설정 (풀스크린 모달)
              +---> 리소스 관리 (풀스크린 모달)
              +---> 카드 클릭 -> 에이전트 팝업 (오버레이 모달)
              +---> 채팅 패널 (우측 슬라이드)
```

### 3-2. Avatar Bar 명세

#### 위치 및 크기

- **위치**: TopNav 바로 아래, 카드 플로우 영역 위
- **높이**: 64px (패딩 포함)
- **배경**: 투명 (카드 플로우 영역과 자연스럽게 연결)
- **패딩**: 좌 `64px` (사이드바 폭만큼), 상하 `12px`

#### 아바타 구성

| 속성 | 값 |
|------|-----|
| 아바타 크기 | 36px 원형 |
| 아바타 간격 | 8px |
| 아바타 내용 | 역할별 아이콘 또는 이름 첫 글자 |
| 아바타 보더 | 2px solid (계층 색상: Main=차콜, Part=부서색, Sub=부서색 200, Instance=그레이) |
| 호버 | 이름 툴팁 + scale 1.1 |
| 클릭 | 해당 카드로 스크롤 + 하이라이트 |

#### 뱃지 규칙

| 뱃지 유형 | 표시 조건 | 색상 | 위치 |
|-----------|----------|------|------|
| 숫자 뱃지 (하위 에이전트 수) | Main, Part, Sub | `--badge-coral` (#E8606D) | 아바타 우하단 |
| 승인 대기 뱃지 | 승인 요청 있을 때 | `--status-pending` (#F5A623) | 아바타 우상단 |
| 에러 뱃지 | 에러 상태일 때 | `--status-error` (#F06060) | 아바타 우상단 |
| 상태 도트 | 항상 | 상태 색상 | 아바타 하단 중앙 |

- 뱃지 크기: 16px 원형, 폰트 10px Bold, 흰 텍스트
- 상태 도트: 8px 원형, 2px 흰 보더
- 뱃지 우선순위: 에러 > 승인 대기 > 숫자 (동시 표시 시 에러가 우선)

#### 정렬 순서

1. Main (항상 첫 번째)
2. Part들 (생성 순서)
3. 각 Part의 Sub들
4. 각 Sub의 Instance들
5. 계층 간 4px 세퍼레이터 라인 (연한 회색)

### 3-3. 4컬럼 카드 플로우 명세

#### 컬럼 구조

| 컬럼 | 역할 | 카드 수 | 배경 |
|------|------|---------|------|
| 컬럼 1: Main | 비서실장, 모든 지시의 출발점 | 항상 1개 | 투명 |
| 컬럼 2: Part | 부서장들, 업무 도메인별 분류 | 0~N개 | 투명 |
| 컬럼 3: Sub | 팀장들, 프로젝트 단위 | 0~N개 | 투명 |
| 컬럼 4: Instance | 실행 에이전트, 실제 작업 수행 | 0~N개 | 투명 |

#### 컬럼 레이아웃

- **컬럼 배경**: 없음 (투명) -- SugarCRM 핵심 원칙. 카드만 부유
- **컬럼 라벨**: 각 컬럼 상단에 연한 대문자 텍스트 (11px, `--text-tertiary`, SemiBold)
- **카드 간 세로 간격**: 12px
- **컬럼 간 가로 간격**: 32px
- **컬럼 너비**: 균등 분배 (각 25%), 최소 너비 220px
- **세로 스크롤**: 카드가 많을 때 컬럼별 독립 스크롤
- **가로 스크롤**: 화면 너비 부족 시 전체 가로 스크롤

#### 커넥션 라인 규칙

커넥션 라인은 SVG 레이어로 카드 플로우 영역 위에 absolute position으로 렌더링한다.

| 속성 | 값 |
|------|-----|
| 색상 (기본) | `--connection-line` (#D1D5DB) |
| 색상 (활성) | `--connection-line-active` (#7C5CFC) |
| 두께 | 1.5px |
| 스타일 | 실선 (기본), 점선 (비활성 관계) |
| 화살표 | 끝점에 작은 삼각형 마커 (4px) |
| 곡률 | 완만한 베지어 커브 (수평 시작 -> 곡선 -> 수평 도착) |

**활성 조건**: 카드 호버 또는 선택 시, 해당 에이전트와 연결된 모든 라인이 `--primary-500`으로 변경되고, 나머지 라인은 opacity 0.3으로 페이드.

**연결 포인트**:
- 출발: 카드 우측 중앙
- 도착: 카드 좌측 중앙
- Main -> 하위 Part 전체에 1:N 연결
- Part -> 소속 Sub에 1:N 연결
- Sub -> 소속 Instance에 1:N 연결

### 3-4. 카드 명세

#### 공통 카드 스타일

| 속성 | 값 |
|------|-----|
| 배경 (기본) | `#FFFFFF` |
| 배경 (활성/다크) | `#10141A` |
| 보더 | 없음 (기본), 상태에 따라 추가 |
| 라디우스 | 16px (`--radius-card`) |
| 그림자 | `0 2px 8px rgba(0,0,0,0.06)` |
| 그림자 (호버) | `0 4px 16px rgba(0,0,0,0.10)` |
| 패딩 | 14px |
| 레이아웃 | 좌측 원형 아바타 + 우측 텍스트 (수평) |
| 호버 | translateY(-2px) + 그림자 강화, 200ms |
| 클릭 | 에이전트 팝업 모달 열기 |
| 액션 아이콘 | 항상 표시 (호버 시가 아님) |

| 항목 | 값 |
|------|-----|

#### 메시지 유형

|------|------|---------|

| 오류 보고 | 빨간 좌측 보더 말풍선 + 에러 상세 | 에러 로그 링크 |

| 진행 보고 | 프로그레스 바 인라인 | 없음 |

- 타이핑 인디케이터: Main이 응답 준비 중일 때 "..." 애니메이션

## 4. 상태별 시각 표현 규칙

### 4-1. 상태 정의

| 상태 | 코드 | 의미 |
|------|------|------|
| Active | `active` | 현재 작업을 수행 중 |
| Idle | `idle` | 작업 없이 대기 중 |
| Pending | `pending` | 대표의 승인/결정을 대기 중 |
| Error | `error` | 오류 발생, 자동 재시도 실패 |
| Stopped | `stopped` | 대표에 의해 수동 정지됨 |

### 4-2. 시각 요소별 규칙

| 요소 | Active | Idle | Pending | Error | Stopped |
|------|--------|------|---------|-------|---------|
| **카드 배경** | `#10141A` (다크) | `#FFFFFF` | `#FFFFFF` | `#FFFFFF` | `#F8FAFC` |
| **카드 보더** | 없음 | 없음 | 2px `#F5A623` | 2px `#F06060` | 없음 |
| **카드 텍스트** | `#FFFFFF` | `--text-primary` | `--text-primary` | `--text-primary` | `--text-tertiary` |
| **상태 도트** | `#5B9BF7` | `#A0AEC0` | `#F5A623` | `#F06060` | `#E2E8F0` |
| **아바타 바 도트** | `#5B9BF7` | `#A0AEC0` | `#F5A623` | `#F06060` | `#E2E8F0` |
| **커넥션 라인** | `#7C5CFC` (호버 시) | `#D1D5DB` | `#F5A623` | `#F06060` | `#E2E8F0` (점선) |
| **글로우** | 없음 | 없음 | `0 0 16px rgba(245,166,35,0.3)` 펄스 3s | `0 0 16px rgba(240,96,96,0.3)` 펄스 2s | 없음 |
| **아이콘** | 기어 회전 (작음) | 없음 | 봉투 아이콘 | 느낌표 아이콘 | 일시정지 아이콘 |
| **카드 opacity** | 1.0 | 1.0 | 1.0 | 1.0 | 0.6 |

### 4-3. 애니메이션 규칙

| 상태 전환 | 애니메이션 |
|-----------|----------|
| 모든 상태 -> Active | 배경색 페이드 (흰 -> 다크), 300ms, ease-default |
| Active -> 모든 상태 | 배경색 페이드 (다크 -> 흰), 300ms, ease-default |
| 모든 상태 -> Pending | 노란 보더 페이드인 + 글로우 시작, 300ms |
| 모든 상태 -> Error | 빨간 보더 페이드인 + 글로우 시작 + 카드 shake(좌우 2px, 300ms, 1회) |
| 모든 상태 -> Stopped | opacity 1.0 -> 0.6, 300ms |
| Stopped -> Active/Idle | opacity 0.6 -> 1.0 + 배경 전환, 300ms |
