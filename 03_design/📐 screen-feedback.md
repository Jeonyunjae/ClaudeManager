> **📌 응답 — 4-Column Flow 설명:**
> 
> 현재 대시보드 프로토타입(`dashboard-prototype.html`)에서 Main → Part → Sub → Instance 4개 컬럼으로 나뉜 카드 영역이 바로 "4-Column Flow"이다.
> 
> ```
> ┌─────────┬─────────┬─────────┬─────────┐
> │ Main    │ Part    │ Sub     │ Instance│
> │ 컬럼    │ 컬럼    │ 컬럼    │ 컬럼    │
> │         │         │         │         │
> │ [카드]  │ [카드]  │ [카드]  │ [카드]  │
> │ [카드]  │ [카드]  │         │         │
> └─────────┴─────────┴─────────┴─────────┘
> ```
> 
> 이 영역이 "전체 의견"에서 피드백한 **업무 추적 대시보드의 핵심 영역**이다.
> 전체 의견의 1~16번 피드백이 모두 이 영역에 대한 것이므로, 전체 의견 기반으로 재설계할 예정.
> 
> 즉, **3-5 = 전체 의견에서 논의한 대시보드 카드 영역과 동일한 항목**이다.

### SCR-05. CLI 탭 — `popup-cli.html`

- [x] 승인
- [ ] 수정

**수정 사항:**
- cli 데이터는 어디서 어떻게 관리하나?
- cli는 서버가 종료되면 초기화 되고 서버가 시작했을때부터의 데이터만 볼수있도록 구성하나?
- 데이터 전체를 보려면.대화탭으로 이동하여 보도록 구성되나?

> **📌 응답:**
> 1. **CLI 데이터 관리:** 서버 측에서 **tmux 세션 + node-pty**로 터미널을 관리한다. 프론트엔드는 **xterm.js**로 렌더링. DB에 저장하지 않는다.
> 2. ✅ **서버 종료 시 초기화된다.** tmux 세션은 메모리 기반이므로 서버 재시작 시 세션이 사라진다. 서버 시작 이후의 실시간 터미널만 표시.
> 3. ✅ **과거 전체 데이터는 대화 탭에서 확인한다.** 대화 탭의 메시지는 `conversations` + `messages` 테이블에 영구 저장되므로, CLI에서 날아간 이력도 대화 기록에서 찾을 수 있다.
> 
> 즉 CLI = **실시간 터미널 창** (휘발성), 대화 = **영구 기록** (DB 저장).

## 4. 전체 의견

> 위 항목에 포함되지 않은 전체적인 피드백을 자유롭게 작성해주세요.

**의견:**
대시보드의 카드 부분의 수정할 부분이 있다.
1. 내가 원하는 대시보드는 내가 메인에게 어떤일을 시켰는지 알고싶다.
2. 메인에서 수행하지 않은 업무가 어떤게 있는지 파악하고 싶다.
3. 크게 5단계로 나눠져있다. (나, main, part, sub, instance)
4. 시작적으로 표현되어야 하는 단계는 4개 (main, part, sub, instance)이다.
5. 단계 4개는 새로(컬럼 행식)로 구역을 나눠 표현한다.
6. 오브젝트들은 대기중인 인스턴스를 숫자로, 진행중, 대기중, 완료 상태를 특정 아이콘 모양으로 표현한다.
7. main은 나의 잔업 업무리스트를 표현한다. 
8. 메인카드에서는 대기 업무 수를 카운팅해서 ui 상으로 보여준다.
9. 팝업창을 띄울수 있다.
10. 요청사항의 결과물을 승인하는 어떻게 해야할지 모르겠다.
11. part를 처음 등록할때 skill등을 해야한다. main과 대화하면서 Part의 skill을 함께 등록한다.
12. 프로젝트를 만들수 있다.
13. part 카드에서는 잔여 업무 카운팅을 하여 잔여 업무를 표현한다. 노트에서 skill을 변경할수 있다.
	1. 스킬 변경은 main과 대화하며 바꾸며 좋을까?
14. part를 선택하면 해당 파트의 세부 프로젝트 sub(3번째) 단계에서 표현된다. 
15. part에서는 선택한 색상과 sub 단계의 색상을 같이하여 해당 part의 프로젝트이다.를 인지할수 잇도록 한다.
16. 프로젝트의 잔여 업무 카운팅을 하여 표현한다.

내가 생각했을때는 이런식으로 ui 플로우가 흘러갔으면 좋겠다.

> └──────────┴──────────┴──────────┴──────────┘
> ```

> ### 컬럼별 상세
> 
> | 컬럼 | 내용 | 인터랙션 |
> |------|------|----------|
> | **Main** | 내가 Main에게 지시한 업무 리스트. 대기 업무 수 카운팅 표시. 🟡 승인 대기 항목 포함 | 카드 클릭 → 팝업 |
> | **Part** | 등록된 Part 목록. 각 카드에 잔여 업무 카운트 + 상태 아이콘 표시. Part 색상 지정 | Part 클릭 → 3컬럼 필터링 |
> | **Sub** | 선택한 Part의 하위 프로젝트. **Part와 동일 색상**으로 소속 인지. 잔여 업무 카운트 | Sub 클릭 → 4컬럼 필터링 |
> | **Instance** | 선택한 Sub의 실행 에이전트. 진행/대기/완료 상태 아이콘 | 카드 클릭 → 팝업 |
> 
> ### 카드 표현 규칙
> 
> | 요소 | 표현 |
> |------|------|
> | 상태: 진행중 | 🔵 (파란 원) |
> | 상태: 대기중 | 🟡 (노란 원) |
> | 상태: 완료 | 🟢 (녹색 원) |
> | 상태: 오류 | 🔴 (빨간 원) |
> | 대기 업무 수 | 숫자 뱃지 (예: `3`) |
> | Part 색상 | 사용자가 Part 등록 시 선택, Sub 컬럼도 동일 색상 적용 |
> 
> ### UI 플로우 (인터랙션 흐름)
> 
> ```
> 1. 페이지 로드 → Main 컬럼에 업무 리스트 표시 + Part 컬럼에 전체 Part 표시

> 4. 아무 카드 클릭 → 팝업 열기 (정보/CLI/대화/로그/노트)
> ```
