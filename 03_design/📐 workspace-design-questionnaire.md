> **SugarCRM이 표현하는 비즈니스:**
> - "Customer Journeys" = 고객 케이스가 처리되는 전체 흐름
> - 4컬럼: Case Allocation → Issue Identification → Technical Resolution → New Tasks
> - 각 카드 = 하나의 업무 단계 (담당자 아바타 + 작업 내용)
> - 다크 카드 = 현재 활성 처리 중인 단계
> - 커넥션 라인 = 업무 흐름 방향
> - 하단: 지식 테이블 + 도넛 차트 = 통계/현황
>
> **우리 시스템에 대입하면:**
> - "Agent Journeys" = 에이전트가 작업을 처리하는 전체 흐름
> - 4컬럼: Main → Part(부서) → Sub(팀) → Instance(에이전트)
> - 각 카드 = 하나의 에이전트 (상태 + 작업 내용)
> - 커넥션 라인 = 지시/보고 흐름

## 1. 비즈니스 흐름

### Q1. 사용자(나)가 Main에게 지시하는 방식은?

> 예시:
> - A) 채팅창에서 텍스트로 지시
> - B) CLI 터미널에서 명령어 입력
> - C) 둘 다 가능
> - D) 기타:

**답변:**
1. 둘다.
2. Main, Sub는 cli가 나한테 보이고 나와 대화를 할수 있어야한다.
	1. 대체적으로는 Main이 진행한다.
	2. sub, instance에게는 질문은 할수있다.

---

### Q2. Main이 Part/Sub/Instance를 자동 생성하나, 사용자가 직접 만드나?

> 예시:
> - A) Main이 판단해서 자동 생성 (사용자는 지켜봄)
> - B) 사용자가 UI에서 직접 생성
> - C) Main이 제안하고 사용자가 승인하면 생성
> - D) 기타:

**답변:**
1. 사용자(나)가 Main에게 part를 만들자 요청한다.
2. main과 cli창 또는 대화를 통하여 part의 스킬 작성
	1. part마다 만드는 사유로는 part마다 잡을 진행하는 방식이 다르기 때문이다.
3. Sub는 프로젝트별로 만들어 지기 때문에 해당 Part의 스킬을 사용하여 구성하려한다.
4. 사용자는 main과 대화(채팅, cli)하여 해당 프로젝틑에 대해서 얘기하고 어떤 part에 구성할지 정의한다.(기준에 존재하면 part에 추가, 없으면 신규 part추가)
5. 사용자는 main과 대화를 하여 만들어둔 스킬을 활용하여 sub, instance를 구성한다.
6. 사용자는 main에게 특정 파트에 프로젝트를 수행하려한다. 라고 대화 또는 cli를 통하여 Sub를 만든다.
7. 대부분의 대시보드에서 진행하는 작업은 main을 통하여 진행을 한다.
8. 프로젝틀별로 아이콘을 만들어서 상징을 만들도록 한다.(도식화할때 사용한다.)
