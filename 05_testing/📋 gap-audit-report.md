## 크리티컬 갭 (시스템 동작 불가)

### GAP-1. 백엔드 오케스트레이션 엔진 전체 미구현
**영향 기능**: F001~F012, F019~F021, F032~F033, F040~F046, F057~F058, F070~F072
**설계 요구**: Main → Part → Sub → Instance 4계층 오케스트레이터가 tmux 세션에서 Claude Code를 실행하고, Hooks로 이벤트를 수집하며, 노트 기반으로 컨텍스트를 관리
**실제 구현**: DB 테이블과 REST API(CRUD)만 존재. **tmux 세션 생성, Claude Code 실행, Hooks 이벤트 수집, .orchestrator/ 파일 관리 — 전부 없음**
**핵심 문제**: 웹앱은 "에이전트 정보를 보여주는 UI"만 있고, 에이전트를 "실제로 실행하는 엔진"이 없다

### GAP-2. Skill 실행 엔진 미구현
**영향 기능**: F001~F007, F009
**설계 요구**: `project-part.sh` 같은 bash Skill을 schema/execute 모드로 실행. source 기반 상속, 폴더 생성, Hooks 설정, 승인 정책 파일 생성까지 자동화
**실제 구현**: `/api/skills/[name]/execute`는 DB에 Part 레코드를 INSERT할 뿐. **bash 스크립트 실행 없음, 폴더 생성 없음, 상속 처리 없음**

### GAP-3. WebSocket 서버 미구현
**영향 기능**: F013, F015, F028, F057, F058
**설계 요구**: ws 기반 별도 WebSocket 서버. 20개 이벤트 타입 (agent:status, approval:new, cost:update 등)
**실제 구현**: 클라이언트 측 `src/lib/ws.ts`만 존재. **서버 측 WebSocket 핸들러 없음**. 실시간 업데이트 불가

### GAP-4. 3D 워크스페이스 미구현
**영향 기능**: 워크스페이스 뷰 전체 (컨셉의 핵심)
**설계 요구**: Three.js + React Three Fiber로 3D 카툰 메타버스. 캐릭터 이동, 접촉 기반 상호작용, 말풍선, 모션
**실제 구현**: `workspace/page.tsx`에 "3D" 텍스트를 보여주는 placeholder div. **Three.js 코드 0줄**

### GAP-5. 터미널 양방향 통신 서버 미구현
**영향 기능**: F057, F058
**설계 요구**: node-pty로 서버 측 PTY 할당, WebSocket으로 stdin/stdout 양방향 릴레이
**실제 구현**: 클라이언트 xterm.js UI만 존재. **node-pty 서버 없음**. 터미널 연결 불가

## 주요 갭 (기능 동작 불완전)

### GAP-6. 브라우저 푸시 알림 미구현
**영향 기능**: F029
**설계 요구**: Web Push API + service worker
**실제 구현**: 대시보드 내 알림 드롭다운만 있음. **Service Worker 없음, Push subscription 없음**

### GAP-7. 오류 로그 — 시스템 에러 DB 저장 미구현
**영향 기능**: F034
**설계 요구**: 에러 메시지, 스택 트레이스, 재시도 횟수, 최종 상태 전체 저장
**실제 구현**: Hooks로 외부에서 보내는 에러만 저장. API Route 내부 catch에서 console.error만 호출, **DB 저장 안 함**

### GAP-8. 자동 백업 미구현
**영향 기능**: F068
**설계 요구**: 일 1회 자동 백업 (주기 설정 가능)
**실제 구현**: 수동 백업(POST /api/backups/manual)만 있음. **스케줄러/cron 없음**

### GAP-9. LiteLLM 통합 미구현
**영향 기능**: F044, F045, F046
**설계 요구**: 모든 모델 호출을 LiteLLM(localhost:4000) 경유, 콜백으로 토큰/비용 자동 수집
**실제 구현**: 비용 데이터를 DB에서 읽는 API만 있음. **LiteLLM 연결 코드 없음**

### GAP-10. .orchestrator/ 파일 감시 미구현
**영향 기능**: F040, F041
**설계 요구**: chokidar로 .orchestrator/ 변경 감지 → DB 동기화 + WebSocket 푸시
**실제 구현**: **chokidar 사용 없음**. 노트 파일을 fs.readFileSync로 직접 읽는 API만 있음

### GAP-11. 마이그레이션 스크립트 미구현
**영향 기능**: F049
**설계 요구**: migrate-to-new-machine.sh (패키징 + 체크섬 + 복원)
**실제 구현**: **스크립트 없음**

### GAP-12. PM2 + launchd 설정 미구현
**영향 기능**: F074
**설계 요구**: ecosystem.config.js + launchd plist
**실제 구현**: **설정 파일 없음**

### GAP-13. 디스크 사용량 모니터링 미구현
**영향 기능**: F017
**설계 요구**: CPU/메모리/디스크/네트워크 실시간 모니터링
**실제 구현**: CPU, 메모리는 os 모듈로 구현. **디스크는 하드코딩 0%, 네트워크도 하드코딩 0**

### GAP-14. 에이전트 큐잉 미구현
**영향 기능**: F071
**설계 요구**: 동시 실행 상한 초과 시 대기 큐
**실제 구현**: max_concurrent_agents 설정값은 있지만 **큐잉 로직 없음**

### GAP-15. 키 만료일 자동 알림 미구현
**영향 기능**: F038
**설계 요구**: 만료 7일 전 자동 알림
**실제 구현**: expiresAt 필드만 저장. **만료 체크 스케줄러 없음**

## 결론

현재 구현은 **"웹앱 UI 껍데기 + DB CRUD"**가 잘 되어 있지만, 이 시스템의 핵심인 **"AI 에이전트를 실제로 실행하고 관리하는 백엔드 엔진"**이 통째로 빠져있습니다.

가장 큰 갭 5개:
1. **오케스트레이션 엔진** (tmux + Claude Code 실행) — 없으면 전체 시스템 동작 불가
2. **WebSocket 서버** — 없으면 실시간 업데이트 불가
3. **3D 워크스페이스** — 없으면 제품 컨셉 구현 불가
4. **LiteLLM 통합** — 없으면 비용 추적 불가
5. **Skill 실행 엔진** (bash 실행) — 없으면 Part 생성 불가
